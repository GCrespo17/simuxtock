# US-003: Sign in and manage session

## Story
**As a** Trader
**I want** to sign in, keep my session active, and sign out
**so that** only I can place orders and view my private portfolio.

## Pre-conditions
- **PRE-01:** Trader has a registered Account.

## Basic flow
- **BF-01:** Trader submits their credentials to sign in.
- **BF-02:** System verifies the credentials and starts an authenticated session.
- **BF-03:** Trader accesses private actions (trading, portfolio) and can refresh their active session or sign out at any time.

## Alternate flows
- **AF-01** (from BF-02): If credentials do not match any registered Trader, then System rejects sign-in without revealing whether the username or password was wrong. → End.
- **AF-02** (from BF-03): If a Trader's session expires or they sign out, then System revokes access to private actions and requires signing in again. → End.

## Acceptance criteria
- **AC-01** (BF-02): Given registered Trader `alice`, when `alice` signs in with valid credentials, then `alice` is authenticated and can access her private portfolio and trading actions.
- **AC-02** (AF-01): Given registered Trader `alice`, when someone submits `alice` with an incorrect password, then sign-in is rejected with a generic authentication error.
- **AC-03** (BF-03, AF-02): Given `alice` is signed in, when `alice` signs out and then attempts to view her portfolio or place an order, then the request is rejected as unauthenticated.
- **AC-04** (BF-03): Given an unauthenticated Guest, when they attempt to access `alice`'s portfolio or orders, then access is rejected.

## Out of scope
- Password reset emails and multi-factor authentication.
